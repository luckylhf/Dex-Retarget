# 0.8.0 本地六项修复与验证（2026-11-06）

本轮只修改 Dex-Retarget，没有连接、同步或运行 luckylhf。独立的 V8 项目与本地上游 Frax checkout 均未修改。下列结果是本地运动学与工程回归，不是全库通过率、动力学或真机验收。

## 修复范围

| 问题 | 当前实现 | 保留的边界 |
|---|---|---|
| 长碰撞窗口被总预算跳过 | 最多 120 帧的重叠窗口；按小幅、中幅、耦合三轮覆盖；完整路径取消 600 帧/12 窗总上限 | 快速路径最多 600 尝试帧；任务级超时仍可中断 |
| 续跑沿用旧验收结论 | 验收和 NPZ 导出拆到 `acceptance.py`；续跑严格比较全部源代码、资产、运行身份 | 改资源配置数值可以；改实现须新批次 |
| 内存预算只学全任务峰值 | 粗阶段和剩余阶段上包络；区分初解复用、冷编译、实际 JAX 缓存；有足够长度跨度后拟合逐帧项 | 观测可能漏掉瞬时峰值，主机/cgroup 保护保持；未做真实 32 路容量验收 |
| 单个难段触发整侧全片回退 | 按帧判断困难；长片原 V8 多起点回退限制到 200 帧窗口；短难窗口直接原算法；密集困难短片的保护上限 600 帧 | 失败局部回滚、接缝检查，最终整段审核；不删除多起点搜索 |
| 墙钟时间抢占求解预算 | 三级按 10/16/24 次外迭代和最多 20000 次 QP 迭代；固定自适应 rho 更新间隔、缩放目标改善数值条件 | 外层任务超时仍有效；局部搜索失败不等于全局无解 |
| IK 分块等参数漏验 | 转换、复用、续跑共用 `conversion_contract`，含 FPS、迭代数、最大帧数、legacy、IK 分块和策略 | 原始输入、准备目标、实现/资产/配置哈希仍独立核对；旧输出不能混入新批次 |

三级相对同一修复前轨迹保持 10°/20°/35° 手臂单轴总改动上限；手掌旋转 10°/20°/30°，手掌位移 3/8/15 cm。耦合档其余关节最多 5°、根部 2 cm。修复成功必须保留接触、地面、逐轴机械限位和速度要求。源动作手臂、手掌、前臂、肘轴和肘弯曲目标权重不再统一乘 0.5/0.25。J1～J3 的偏移正则更轻，鼓励优先使用肩部补偿，同时允许七轴协作。

碰撞窗口内部切口允许调整；外部有效接缝固定。邻接区间复查碰撞和地面，最终八倍插值检查整段。非线性失败的有限中间状态只用作下一级初值，不作为“已修好”结果。各窗口只缓存自身的关节片段，避免窗口数乘整片长度的内存增长。最终导出仍由统一源姿态、接触、安全门槛决定。

## 本地验证

所有执行验证都经 `scripts/check_bounded.py`，295 秒执行预算加最多 5 秒终止清理。没有整库转换。

- 全部自动测试：**176 passed、4 skipped，23.07 秒**。最终窗口缓存改动另通过 22 项定向回归（5.25 秒）。4 项跳过为未通过环境变量开启的私有数据/IK 缓存选测，未计作通过。
- 新回归覆盖 601 帧坏段不丢帧、三级轮次/共同参考、快速预算的 deferred、验收代码与分块变化拒绝续跑、资源数值不改变契约、阶段与缓存隔离、左右臂重复子阶段、长臂回退窗口上限和局部材料接触 QP、学习样本按长度桶压缩。
- 真实机器人碰撞夹具：碰撞消除、浮点导出后限位/逐轴速度，以及耦合修复中固定材料接触位置复查通过。时钟每次人为前进 1000 秒的同一修复仍完成，验证正常三级预算不受墙钟竞争消耗。
- 真实 Frax CLI：LAFAN walk_turn 前 80 帧，转换内部 **6.10 秒**，`accepted`、`flags=[]`、QP 未收敛步数 0，训练 NPZ 导出完成；最终 CLI 产物的实现哈希与交付源码逐项一致，输出文件哈希已核对。

开发中发现过局部回退重复搜索、起身上臂 P95 恶化约 2°，该候选未采用。最终保留有界难窗原 V8 搜索和必要的一次全片连续性拟合；不超过 600 帧且困难区加上下文覆盖至少三分之一的短片，保守直接使用原算法，避免重复拟合及姿态回退。更长动作不能触发这个整段保护。不采用把困难起身时序也强行切块的版本。全片连续性拟合与全片重新搜索分支是不同阶段，后者没有因单个坏段重跑。同时区分严格“跳过逐帧求解”门槛与“已拟合后重做搜索”触发条件；没有把输出质量门槛放宽。
