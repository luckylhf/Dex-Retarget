# 0.7.0 分流、内存学习与手臂跟踪（2026-11-06）

本版实现用户指定的四项改动，统一质量门槛保持
`common_pose_speed_collision_plus_1mm_geometry_v2`。独立V8源码目录未修改；
手臂扩展发生在本项目复制的 `src/dex_frax/v8/arms.py`。

## 路由与输出

- `convert` 默认auto，任何长度均按frax → hybrid → V8，通过即停止。
- `batch` 默认auto，名义时长严格小于60秒才运行frax → hybrid；其余直接V8。
  时长读取BVH头部的Frames × Frame Time，不做试跑或性能预测。
- 短动作失败项进入V8。frax、hybrid优先；V8可填空槽，按长动作优先排队，
  不设全批阶段屏障。原来源速度异常和碰撞单项失败的提前停止规则已移除。
- 按完整BVH SHA256去重，重复id写入 `source_aliases.json`。
  同内容但source解释冲突时拒绝启动。
- 单文件auto阶段目录在输出根目录下；固定模式输出结构不变。
  通过的训练文件只从 `accepted.json` 读取。完成转换与质量通过分别记录。

## 内存学习

工作进程发送初解复用、冷编译、求解、后处理、审核及空闲缓存状态事件，
调度器采样PSS。按模式、来源、JAX缓存状态维护完整任务的峰值包络，
至少两个完整任务后才替换初始驻留预算；冷编译增量单独学习。
失败任务或仅启动阶段采样不会降低预算。

核验复用初解、热kernel命中及纯V8不产生共享编译预留。
已承诺复用的初解若核验失败，hybrid失败后升级独立V8，避免未预算的冷求解。
所有采样、学习及当前准入估算均保存在批次记录和状态目录中。
通过CLI或热配置可停用学习，主机预留/cgroup硬限制持续生效。

学习的是观测峰值，不能保证捕获所有瞬时峰值；它用于调度，并不代替硬限制。
变化后的源码、资产、运行环境及IK参数使用独立学习命名空间。

## 手臂改动与回退

平滑区间复用已有分支。先拟合J1/J2/J3，必要时才联合七轴；
J4～J7原有肘弯曲、肘轴/肘窝、前臂和手掌轴、腕部软限位目标保留。
接触变化、进入限位附近或近伸直区、目标跳变、持续误差上升才触发候选搜索。
近伸直状态采用滞回，异常时序只在有界局部窗口处理，失败回到原全片求解。

初版在stumble缓存窗口出现上臂P95退化，已拒绝该方案并增加保护：
有上肢支撑或原始姿态持续超标的侧臂保留原算法；新结果持续姿态超标时
只重算该侧。当前回归未出现这项退化。
