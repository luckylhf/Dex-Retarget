# 0.6.1 持续调度与内存预算（2026-11-06）

0.6.0远端LAFAN试跑暴露了预算高估：15个长动作预测43.096 GiB，另有共享编译预留2.75 GiB；160.6秒现场实际PSS合计10.960 GiB、scope占用12.479 GiB、主机可用47.840 GiB。进入修复和审核后，已观察scope峰值约19.04 GiB。较低瞬时值不能当作全流程峰值，但128 KiB/帧的预算确实压低了并发。

用户明确要求删除近期生成数据、改好后重新运行。已停止0.6.0任务并确认无转换进程；删除LAFAN的0.5.1全量、对应launchcheck、0.6.0试跑，以及BONES的0.5.1全量和对应launchcheck，共5个目录、约8.04 GiB。仅保留去重清单和小型审计记录；原始BVH、旧V8基线、环境和机器人资产未删除。本轮重跑范围为77条LAFAN，不启动BONES。

## 实现

- `managed_batch.py`：动作完成后立即进入下一级待派发队列；优先首轮frax，有槽位和内存就派发。不同动作可并行处于frax、hybrid、v8；没有全批阶段屏障。
- `resource_policy.py`：每2秒重读外部资源JSON，校验后同时更新在途和待派发预留。非法配置保留最近有效值，变更和拒绝均记录。
- 默认Frax驻留1 GiB、hybrid1.5 GiB、V8 1 GiB，各加每输出帧32 KiB；非纯V8时共享编译预留2.75 GiB。内存估算仍须根据实际峰值复核。
- 保持32槽启动上限、主机预留10 GiB、磁盘预留80 GiB和本次48 GiB cgroup硬限制；热加载不能绕过这些保护。
- IK、接触、姿态、避碰、导出及验收代码保持0.6.0实现；仅版本/发布身份随调度版本更新。
