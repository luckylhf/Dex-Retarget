# 0.5.0 自动分级批处理验证

默认单次转换和固定模式 batch 均保持 frax；只有 `batch --mode auto` 开启整批 frax → 未通过项 hybrid → 剩余项 V8。全部阶段使用统一持续上肢、姿态、接触、穿地、速度与碰撞审核。通过即停止升级，最终入库索引为 accepted.json。

验证结果：

- 118 项测试通过，46 条依赖警告。覆盖阶段顺序、提前通过、超时后工作进程重建、中断清理、总预算、输入隔离、路径/ID 校验、导出哈希校验、清单快照指纹及初解复用失效。
- 私有 12 动作回归完成 18 次真实尝试：12 次 frax、3 次 hybrid、3 次 V8；9 项通过，3 项仍待审。三个后续阶段都没有放宽门槛强行入库。
- 12 条 frax 轨迹与 0.4.1 输出逐字节一致。三个 hybrid 均成功复用经过校验的首轮原始 IK；ground 的复用结果与独立 hybrid 重算逐字节一致。
- 损坏 BVH 与正常动作混合批处理：坏输入只尝试一次，正常动作仍通过。实际 0.05 秒总预算测试终止工作进程，没有留下训练文件；固定模式批量与安装后的命令行入口均实测。
- 通过索引的 9 个训练文件、源输入哈希、最终命令行运行身份及 0.5.0 wheel 内容已核验。所有测试数据与产物位于忽略的 regression_local/；没有上传。

剩余 ground、get_up、stumble 保留全部阶段预览与具体错误。这一轮交付的是调度、复用和故障管理，没有宣称提升通过率或解决所有动作。测试与回归曾同时运行，耗时不作为速度基准。

本地证据：`regression_local/cascade_050/release_all/batch.json`、`accepted.json`、`tests_final.log`、`release_validation.json`。清单快照指纹的最后修正另经单元测试及最终安装入口验证。没有动力学、策略跟踪或真机验证；未加入自动续跑或多工作进程并行。
